CHATBOTERLY 1.2.5 — MAPA DE CÓDIGO

app.py
- Servidor Flask y endpoint /chat.
- Detección directa de acciones web.
- Mantener intacto salvo cambios específicos del backend.

memory.py
- Memoria persistente mediante SQLite.

web_tools.py
- Definición y apoyo de acciones web.

memory.db
- Base de datos de memoria de Erly.

index.html
- Estructura principal de la interfaz.
- Avatar: torso body.png + rostro + manos flotantes.
- Sensor de cámara conservado pero oculto/desactivado.
- Carga face.js, permissions.js y chat.js.

style.css
- Diseño general.
- Rostro programado.
- Posicionamiento y apariencia del torso.
- Manos flotantes tipo Wii.
- Responsive móvil.
- En 1.2.4.2 se corrigió la composición del avatar para evitar solapamientos.

face.js
- Rostro, mirada, parpadeo y emociones.
- SENSOR_ENABLED = false.
- Sensor MediaPipe conservado para futuro.
- Sistema de manos virtuales.
- window.ErlyHands: API pública para poses y movimiento.

chat.js
- Envío de mensajes.
- Reconocimiento de voz.
- Voz de Erly.
- Emociones según respuesta.
- Selección de pose de las manos.
- Solicitud de permiso para acciones web.

permissions.js
- Panel de autorización.
- requestPermission() → muestra permiso.
- executeAction() → ejecuta acciones autorizadas.
- allowPermission → autorización y ejecución.
- denyPermission → cancelación.

body.png
- Torso/busto visual de Erly.
- PNG recortado para eliminar márgenes transparentes excesivos del archivo original.
- Se mantiene el mismo nombre para no romper referencias existentes.

CHATBOTERLY 1.3.2
============================================================

NUEVO:
- Panel de chat opcional mediante el botón "CHAT".
- El historial de mensajes se muestra solo cuando el usuario activa el panel.
- Las respuestas de Erly aparecen progresivamente en el panel, simulando escritura.
- Botón para limpiar la conversación visible.
- Se conserva el chat de backend, voz, memoria, emociones y gestos.

TIKTOK:
- search_tiktok conserva la detección de "busca X en TikTok".
- `search_tiktok` prueba primero una apertura mediante esquema nativo `snssdk1233://search?...`.
- Después prueba un App Link HTTPS dirigido al paquete de TikTok.
- Si ninguno de los dos mecanismos consigue abrir la búsqueda nativa, se usa como último respaldo la búsqueda web de TikTok.
- La ruta nativa de búsqueda no está documentada oficialmente por TikTok; esta implementación se mantiene como prueba controlada y no altera las demás acciones.
- No se redirige intencionadamente a Google.

NOTA TÉCNICA:
TikTok documenta integración Android mediante OpenSDK y reconoce los paquetes
com.zhiliaoapp.musically y com.ss.android.ugc.trill para escenarios Android.
La búsqueda interna por texto no está documentada como una API pública; por eso
la versión 1.3.2 usa intento nativo + respaldo web.
